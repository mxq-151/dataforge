### 修复：选中色随光标移动而变

现象：底部提示「已选中 N 项」正确，但光标移到哪一行，哪一行就变成选中蓝。

根因（CSS 级联 + 库的 inline style）：`react-file-navigator` 的行背景走 inline style，**悬停行**与**它内部的单选行**都写 `background-color: accentColor`；而 `explorerConfig.accentColor` 正是 `#094771`（与选中蓝相同）。原 CSS 两条 hack 规则特异性相同（都是 (0,2,4)），`[style*="background-color"] → #094771` 写在 `:hover → #2a2d2e` 之后，于是带 inline 背景的行（= 悬停行）一律显示成选中蓝。

修复：
- `ExplorerPanel.css`：删掉这两条 hack，改为
  - `.file-navigator-wrapper div[tabindex]:hover { background-color: #2a2d2e !important }`
  - `.file-navigator-wrapper div[tabindex].explorer-row--selected, ...:hover { background-color: #094771 !important }`（写在 hover 之后，特异性相等时以顺序取胜）
- `ExplorerPanel.tsx` `syncSelectionStyles`：不再写 inline 背景（删掉 `SELECTED_ROW_BG`），只 `classList.toggle('explorer-row--selected')` + `removeProperty('background-color')` 清掉库写的 inline，视觉完全交给 CSS
- 级联要点：**作者样式表里的 `!important` 能压过 inline 的普通声明**（style 属性属于作者普通声明），所以 `:hover` 的 `!important` 足以盖掉库写的 inline 背景
- 测试新增第 9 个用例：断言选中行不得残留 inline `background-color`（守住「选中态只用 class 表达」这一前提）
- 验证：tsc --noEmit 无错误；`ExplorerPanel.multiSelect.test.tsx` 9 passed

### 性能：智能体对话模块长内容 CPU 优化（第二轮，诊断驱动）

现象：智能体回复很长 / 对话历史很长时 CPU 占用高。

诊断（新增 `scripts/ai-bench-profile.mjs`，用 CDP Profiler 域抓 V8 CPU profile，按
`函数@文件:行` 聚合 self time）：
- 关键发现：基准页自带的「编辑器输入探针」自身消耗约 580ms Monaco CPU，会淹没有效信号 →
  加 `--typing false` 规避后信号才干净。
- 热点 1：`PacedMarkdown` 的稳定前缀是**整段**交给一个 ReactMarkdown 解析的，
  前缀每前进一个段落就整段重解析 → 仍为 O(n²)（24K 文本累计解析量 >10 倍文本量）。
- 热点 2：`flushDeltas` 每 33ms 把 accumDelta 写回 `messages` → 整棵时间线重算
  （`constructMessageRows`/`groupParts`/`reuseTimelineRows`/`entryByID`/`assistantCopyPartID`）。
  提交次数对账：long 场景 599 次 ≈ 200（flush，33ms）+ 200（打字机，32ms）。
- 对照：conv-40t（40 轮历史）单核占用 56.6% > long 的 30.4%，证明成本随历史长度增长。

改动：
1. `useOpencodeEvents.ts`：新增 `subscribePartText(partID, listener)`（~32ms 合并通知）；
   `flushDeltas(force?)` 改为「首次上屏才写 messages，后续增长只走 ref + part 级订阅」；
   **用户消息仍全量同步**（回滚回显读 messages）；`force=true` 用于 idle/重连兜底。
2. `PacedMarkdown.tsx`：新增 `splitStableBlocks` + `blockCacheRef`，稳定前缀按顶层块缓存元素，
   只解析新增块 → O(n²)→O(n)。保守合并：1~3 空格缩进块、含引用式链接定义（含 GFM 脚注）的块。
3. `MessageTimeline.tsx`：抽 `VirtualRow`（React.memo），行级跳过重渲染。
4. `UserMessageDisplay.tsx`：`Intl.DateTimeFormat` 模块级复用。
5. `TextPartDisplay` / `ReasoningPartDisplay`：`useSyncExternalStore` 订阅 part 文本。

打通链路：`PartsDataContext` / `MessageTimeline` / `AIPanel` / `AIBenchPage` / `useOpencodeClient` 加
`subscribePartText`（`DevAssistantView` 的 `modifiedchatBackend` 用 spread，无需改）。

结果（vs 优化前）：

- **渲染完整性**：renderedChars 前后逐字节一致（6558 / 19617 / 13087）→ 无丢字
