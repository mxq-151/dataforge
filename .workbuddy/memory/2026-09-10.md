### 修复：选中色随光标移动而变

现象：底部提示「已选中 N 项」正确，但光标移到哪一行，哪一行就变成选中蓝。

根因（CSS 级联 + 库的 inline style）：`react-file-navigator` 的行背景走 inline style，**悬停行**与**它内部的单选行**都写 `background-color: accentColor`；而 `explorerConfig.accentColor` 正是 `#094771`（与选中蓝相同）。原 CSS 两条 hack 规则特异性相同（都是 (0,2,4)），`[style*="background-color"] → #094771` 写在 `:hover → #2a2d2e` 之后，于是带 inline 背景的行（= 悬停行）一律显示成选中蓝。

修复：
- `ExplorerPanel.css`：删掉这两条 hack，改为
  - `.file-navigator-wrapper div[tabindex]:hover { background-color: #2a2d2e !important }`
  - `.file-navigator-wrapper div[tabindex].explorer-row--selected, ...:hover { background-color: #094771 !important }`（写在 hover 之后，特异性相等时以顺序取胜）
- `ExplorerPanel.tsx` `syncSelectionStyles`：不再写 inline 背景（删掉 `SELECTED_ROW_BG`），只 `classList.toggle('explorer-row--selected')` + `removeProperty('background-color')` 清掉库写的 inline，视觉完全交给 CSS
- 级联要点：**作者样式表里的 `!important` 能压过 inline 的普通声明**（style 属性属于作者普通声明），所以 `:hover` 的 `!important` 足以盖掉库写的 inline 背景
- 测试新增第 9 个用例：断言选中行不得残留 inline `background-color`（守住「选中态只用 class 表达」这一前提）
- 验证：tsc --noEmit 无错误；`ExplorerPanel.multiSelect.test.tsx` 9 passed
