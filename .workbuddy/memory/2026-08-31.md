# 2026-08-31 工作日志

## 修复：Java 跳第三方 JAR 报 "Message could not be parsed."

### 现象
Java 项目内跳转正常；跳第三方 JAR（如 SparkSession）时 Tab 显示：
```
// 无法加载类源码: SparkSession.class
// Message could not be parsed.
```

### 根因
`java/classFileContents` 请求参数类型是 `TextDocumentIdentifier`（对象 `{ uri }`），
客户端误传了裸字符串。JDT.LS 用 LSP4J 反序列化参数时，`MessageJsonHandler.parseParams`
无法把 JSON string 转成对象 → 返回错误 "Message could not be parsed."。

服务端签名（从 resources/jdtls/plugins/org.eclipse.jdt.ls.core_1.40.0.jar 反编译确认）：
```java
CompletableFuture<String> classFileContents(org.eclipse.lsp4j.TextDocumentIdentifier)
```
实现走 `ContentProviderManager.getContent`：源码附件(SourceContentProvider) →
FernFlower 反编译回退，所以只要参数对，无 sources jar 也能反编译出内容。

VS Code Java 插件（providerDispatcher.ts createJDTContentProvider）传的是 `{ uri: uri.toString() }`。

### 修复
- `src/services/lsp/languageClient.ts`：两处 `sendRequest('java/classFileContents', ...)` 参数
  由裸串改为 `{ uri }`（provideTextDocumentContent 用 `{ uri: uri.toString() }`，
  readJavaClassFileContent 用 `{ uri }`），并加 trace_log 记录返回长度。
- `src/views/dev-assistant/DevAssistantView.tsx`：classFileContents 返回空时显示友好提示，
  区分「无源码附件且反编译失败」与「请求失败」。

### 验证
- tsc：仅剩既有 src/test/setup.ts 缺 vitest 依赖，改动文件 0 错误。
- 新增 `src/services/lsp/classFileContents.test.ts`（4 用例），vitest 4/4 通过。

## 追加：跳第三方 JAR 显示反编译而非源码

修复参数后能出内容了，但显示的是 FernFlower 反编译伪源码，不是 sources jar 里的原始 .java。
原因：`java.maven.downloadSources`（JDT.LS 默认 false，VS Code Java 插件也默认 false）——第三方依赖
无源码附件时 classFileContents 走 ContentProviderManager 降级反编译。

处理：在 `JAVA_INITIALIZATION_OPTIONS.settings.java` 加 `maven.downloadSources: true`。
该设置只在 maven 项目 import 时生效（MavenProjectImporter → m2e setDownloadSources），
改后需重启 DataForge / 切换工作区触发 JDT.LS 重新 import 才会下载；下载涉及网络需先配代理。

## 追加（关键根因修正）：SparkSession 反编译的真正原因

用户确认 SparkSession 有源码（Scala 跳转能看源码）。取证结论：
- 本地 .m2 已有 spark-sql_2.12-3.5.9-sources.jar；m2e container state（data_procs.container）
  里已正确记录 sourceAttachmentPath，source attach 是成功的。
- **真正原因**：SparkSession 是 Scala 写的，sources.jar 里是 `.scala`（org/apache/spark/sql/ 下
  589 个 .scala vs 46 个 .java）。JDT（Java LSP）的 ClassFile.getBuffer() 只认 `.java` 源文件，
  读不到 .scala → 返回 null → 回退 FernFlower 反编译。Metals（Scala LSP）读 .scala，所以 Scala 跳转能看源码。
- 这是 Java 生态固有限制，非 DataForge bug；VS Code 的 Red Hat Java 插件对 SparkSession 同样只反编译。
- 结论：`downloadSources=true` 只对纯 Java 库（Guava/Jackson/commons 等）有效；对 Scala 写的库
  （Spark 等）无效。想看 Spark 源码须用 Scala 视角跳转。JDT.LS 1.40 的 java.maven.downloadSources 默认 false
  （Preferences 构造器 iconst_0 确认）。
