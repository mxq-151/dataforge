## 开发助手「定义跳转」Windows 路径适配（续上一轮修复）

**问题**：Windows 上代码编辑框（Monaco）定义跳转打开的文件路径带 `/`，导致打开失败/路径错乱。

**根因**：Java `File.toURI()` 输出单斜杠 URI（`file:/C:/a/b.java`），JDT.LS/Metals 部分
代码路径在 Windows 上会返回这种形式。上一轮修复只覆盖了 `file:///` 三斜杠变体：
- `uriToPath` 对 `file:/C:/...`、`file:C:/...` 原样返回（startsWith('file://') 不匹配），
  Tab path 直接成了带 `/` 的 URI 字符串；
- `uriKey` 无法归一化这些变体 → 同文件被误判为外部目标 → 重复开 Tab；
- `definitionOpener` 路由判断 `startsWith('file://')` → 单斜杠 URI 落入
  「不支持的定义跳转目标」toast，提示里就是带 `/` 的路径。

**修复**（src/services/lsp/uri.ts 重写 uriToPath/pathToUri + 新增 isFileUri）：
- `uriToPath`：剥 `file:` 后统计前导斜杠数量，兼容 RFC 8089 全部形式
  （`file:///C:/`、`file:/C:/`、`file:C:/`、`file://C:/`盘符当authority、`file://server/share` UNC），
  统一转本地路径（Windows → `C:\a\b.java`）；
- `pathToUri`：畸形 file URI（单斜杠/无斜杠/盘符当 authority）重建为标准 `file:///`；
  Metals readonly 原始 URI 与 UNC 原样保留（服务器靠原始 URI 识别只读文档）;
- `isFileUri`：导出给 DevAssistantView 的 definitionOpener 三分支路由使用；
- pathUtils `HAS_SCHEME`：scheme 至少两个字母（`C:/` 是盘符不是 scheme），file: 任意斜杠数均算 scheme。

**验证**：新增 `src/services/lsp/uri.windows.e2e.test.ts`（7 种 URI 变体 × 转换/同文件判定/
路由分支/往返稳定）；全量 394 测试通过，tsc 无错，`npm run build` 成功。
