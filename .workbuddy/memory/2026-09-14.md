## 本地 docx 编辑踩坑（tencent-local-office-edit / editor_sdk）

1. **`table_id` 是实例级的、重开文档即失效** —— 换个 file_id 后旧 table_id 全部报 `table not found`。
   任何"查一次 table_id 反复用"的脚本都要在**同一实例会话内**跑完。
2. **预览实例会被宿主悄悄回收**：`get_pool_status` 里 `file_path` 变成 `""`、`last_saved_ms: -1` =
   实例已孤儿化，此时 `doc_find` 报 `document is not open`，未保存的编辑全部丢失。
   ⇒ 长脚本要一次跑完并立即 `save_file`。
3. **`save_file` 原地保存会报 `Export file is occupied`**：因为 `wpsoffice` 进程以写模式持有该文件
   （预览面板的引擎）。`close_file` 也释放不掉（WPS 进程独立存活）。
   **绕法**：`save_file` 带 `file_path` 另存新路径可以成功；但要知道这是引擎自锁。
4. **插行会打乱斑马纹**：表格底色是"奇数行 F5F7FA、偶数行无底色"的位置规则，中途插一行会让下方所有行的
   奇偶翻转。修法是插行后用 `doc_set_table_cells` 按行列重刷底色（偶数行给 `FFFFFF` 白填充）。
5. 结论：**这类"源文件是我自己生成的"文档，订正走"改源 + 重新生成"比在 docx 上打补丁更可靠**
   （必须同步改源，否则下次重生成错误复现）。
