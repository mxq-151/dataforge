# 2026-11-06

## 智能体外部信息检索改造方案（已确认方向）

**问题**：智能体通过关键词接口获取库表、血缘、知识库信息，返回大量非目标结果。

**结论**：噪声分两类——结构性（环境 `_test/_gray/_prod` 同名库、分层混排、无权表、跨 namespace）必须服务端规则过滤；语义性（业务口语 vs 英文表名、注释缺失、同义词不通）才交给 agentic search。agentic 解决 precision，不解决 recall。

**已确认选型**：方案 C（检索子代理 + 统一检索接口），三类数据源一起改。

架构分层：
- L1 索引层（dataforge-server）：库表/字段/指标、知识片段、血缘邻接，统一 ID + 权限
- L2 检索接口层：`metadata_search` / `knowledge_search` / `lineage_walk`，统一入参 filters 与出参 `{items,total,truncated,notFound}`
- L3 工具层（opencode 侧）：薄封装，不做业务判定
- L4 检索子代理 `data-retriever`：query 规划 → 多路召回 → 四问判定（环境/分层/权限/命名）→ 证据包；≤3 轮收敛，未命中报 not_found
- L5 主智能体：只消费证据包，产出须引用 evidence

落点：
- `src/hooks/opencode/opencodeInstructions.ts` 的 `infoGatheringPrinciple()` 改为统一 `RETRIEVAL_PROTOCOL`（S1/S2/S3/分析师共用）
- `electron/backend/devAssistantAgents.ts` 注册 `data-retriever` 子代理
- `opencodeInstructions.test.ts` 中相关文案断言需同步（文件头已声明该纪律）

可复用发现：`src/api/assetCatalog.ts` 的 `/api/asset/search` 已支持 types+env+layerCode+domainCode 且服务端 fail-close 权限，可直接作为召回底座。

待定：opencode 发版节奏；服务端是否有向量库/ES；术语表能否机器读取（决定同义扩展实现）。

未做：尚未编码，等待接口方案确认。

## M3 / M4（已完成）

### 关键契约修正
服务端 `WebMvcConfig` 的 `@Primary ObjectMapper` 覆盖了 yml 的 SNAKE_CASE，线上实际是 **camelCase**（`ContractMockMvcSupport` 有说明）。已把 opencode 工具的参数与响应字段全部改为 camelCase（`docTypes`/`topK`/`sectionIndex`/`maxChars`/`layerCode`/`notFound` 等），否则会静默丢参。

### M3-1 术语表词典
- `support/TermDictionary`：从知识库 `business_knowledge` 文档的「术语表」章节解析（Markdown 表格 + `- 术语：别名、英文名` 两种写法），整篇标题含「术语」时全文解析
- `service/RetrievalTermService`：5 分钟 TTL 缓存、最多 200 篇、加载失败 fail-open（空词典）
- `AgentRetrievalService` 召回时并入扩展词，响应新增 `expandedKeywords` 回显（扩展词与原词等权，单术语 ≤3、单次 ≤12）

### M3-2 知识库 BM25
- `KnowledgeSnippetService` 改为先切节、再统一算 df/idf 的 BM25（k1=1.2, b=0.75），标题 ×1.6、章节标题 ×1.2，结果按批内最大值归一到 0~1
- 未做向量检索：知识库无向量索引，接口按「可替换排序器」设计，接向量时只换 `bm25()` 实现

### M3-3 血缘
- 未落「邻接表」：服务端无 Marquez 客户端，做邻接表需要新增配置 + 采集任务 + DDL 迁移，且 Marquez 无全量图导出接口，收益（省一次 search）与成本不匹配
- 改为 `lineage_walk` 节点解析结果 3 分钟 TTL 缓存（上限 100 条），覆盖同一会话重复查询

### M4 评测
