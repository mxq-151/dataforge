## 资产管理 · 资产目录：左右两栏顶部工具带等高（修分界线错开）

**问题**（用户截图）：资产目录页签里，左栏「搜索行 + 引擎视角/规范视角」下方的分隔线，
比右栏「资产详情」头部下方的分隔线低，两条线没连成一条。

**定位**（不用猜，用真实浏览器量）：playwright + 本机 chromium，`file://` 加载一个只含
「`.ac-panel` 真实结构 + 真实 `AssetCatalogPanel.css` + 复刻的 `:root`」的静态页，
`getBoundingClientRect()` 量两侧 `border-bottom` 的 y。
- 改前：左线 y=130，右线 y=111.5 → **错开 18.5px**（900/1080/1280/1440 四个宽度一致）。
- 也顺手查清两处容易踩的点：本项目**没有全局 `box-sizing` reset**；
  `button`/`input` 不继承 `:root` 的 font-family 与 line-height（走 UA 的 Arial + normal），
  所以左栏行高在换字体栈时**不漂移**（实测 5 种字体栈均为 search 34 / views 38 / btn 29）。

**取舍**：两个方向都能对齐 —— ① 收紧左栏 18.5px；② 把右栏头部撑到 92px。
选了 ①：② 会让右栏头部出现 ~31px 死区、且白占内容区高度；① 顺带把左栏控件尺寸
拉回与全站控件一致（搜索框 30 ≈ 普通 `.ac-input` 29；视角按钮 27 = 模块条环境切换按钮 27）。

**改法**（`src/views/asset-catalog/AssetCatalogPanel.css`，4 个选择器）：
- `.ac-side__search`：`margin: 12px 12px 8px` → `10px 12px 5px`，`padding: 5px 8px` → `3px 8px`（高 34 → 30）
- `.ac-side__views`：`padding: 0 12px 8px` → `0 12px`（下沿紧贴分隔线）
- `.ac-viewbtn`：`padding: 5px 8px` → `4px 8px`（高 29 → 27）
- `.ac-main__title`：新增 `line-height: 22px`（避免继承 1.5 得到 22.5，产生半像素差）

结果：73 = 左（10+30+5 + 27+1）= 右（16+22+4+18+12+1），四个宽度下错位 **0.00px**。

**验证**：资产目录模块 4 个测试文件 29 例全过。测量脚本留在 `/tmp/ac-measure/`（`measure.js` 等）。

## 开发助手 · 单文件提交调度：依赖关系改为「只增不删」

**需求**（用户定调）：`SubmitToSchedulerModal` 单文件提交时**不得改动工作流已有依赖关系**——
① 本次任务在工作流中**已存在** → 只更新该节点内容，依赖边一条不动；
② 本次任务为**新增节点** → 原有依赖边全保留，仅按代码头 `@依赖` **补齐**尚不存在的依赖边。

**改动前的病灶**：更新已有工作流时先 `scanLocalHeaderDependencies()` **递归扫描本地项目全部代码文件**，
再 `reconcileWorkflowDependencies()` **整体重建**——提交 A 文件会把 B/C/D 的边按本地文件重写/删除
（reconcile 会丢弃所有 target 的原有入边，并清理孤儿 DEPENDENT 节点）。

**改法**：
- `utils/schedulerMapping.ts` 新增 `addMissingWorkflowDependencies()`（配套 `WorkflowDependencyAddContext/Result`）
  + 私有 `mergeDependentTaskParams()`：保留传入 nodes/edges 全部原样，只补边；跨工作流前置任务复用/补建
  专属 `前置依赖_{任务名}` 节点（已存在则**只并入新条目、按 projectCode|definitionCode|depTaskCode 去重**，
  保留原 code/坐标/轮询参数）。`reconcileWorkflowDependencies` **保持不动**，仅文件夹提交那条链路继续用。
- `SubmitToSchedulerModal`：删掉 `scanLocalHeaderDependencies` 回调与 `parseDependencyHeader` 引用；
  `existingIndex < 0` 才调新函数，`existingIndex >= 0` 完全跳过依赖逻辑。
  **`layoutWorkflowByDependency` 也一并收进 `existingIndex < 0` 分支**——纯内容更新时不重排全图坐标，
  否则「已有节点只改本身」会被全图重排破坏。
  环校验只在**本轮确实新增了边**时跑（避免历史图有环时挡住纯内容更新）。
  UI 提示文案改为「提交新增任务时按代码头 @依赖 补齐前置依赖（不修改工作流已有依赖关系）…」。

**测试**：新增 `src/views/dev-assistant/SubmitToSchedulerModal.dependency.test.tsx`（2 例，端到端断言
update 载荷的 nodes/edges）+ `schedulerMapping.test.ts` 追加 6 例（保留全部原边/不重复加边/补建
DEPENDENT 节点/只并入不删条目/前置不存在告警/自依赖告警）。全量 **70 文件 / 1152 例全过**，`tsc --noEmit` 通过。

## 修复：数据探索「图表分析」模态框无法切换结果集

- **现象**：勾选多个执行结果 → 图表分析，模态框里点「结果 2」标签无反应（始终停在第 1 个结果，
  无法切换后设置图表样式）。
- **根因**：`src/features/execHistory/ChartAnalysisModal.tsx` 的重置 effect 依赖 `activeResult?.id`
  **且**在其中调 `setActiveIdx(0)`。点标签 → `activeIdx=1` → `activeResult.id` 变化 → effect 重跑
  → 立刻 `activeIdx=0` 打回第一个结果（点击在下一渲染即被撤销）。
- **修法**：拆成两个 effect——① 依赖 `[visible, resultsKey]`：`setActiveIdx(0)` + 重置 `chartType`；
  ② 依赖 `[visible, activeResult?.id]`：只按新结果重建横/纵轴，**保留用户已选的图表类型**（不再被打回表格）。
  `resultsKey = results.map(r => r.id).join('|')`，避免每次渲染都触发。
- **测试**：新增 `ChartAnalysisModal.test.tsx` 3 例（默认首个结果 / 点击标签真正切换 / 切换后保留图表类型）；
  临时把 `setActiveIdx(0)` 加回去验证测试确实会挂（2 例失败）。全量 **71 文件 / 1155 例**，
  唯一失败是 `AssetCatalogPanel.lifecycle.test.tsx` 的 `waitFor` 超时——单独跑 9 例全过，属已知高负载误报。
  `tsc --noEmit` 通过。

## 构建产物同步 · 新增 `scripts/sync-opencode-binaries.sh`

**背景**：opencode 重建后 `~/Desktop/opencode/packages/opencode/dist/` 是**按平台三元组分包的 npm 布局**
（`<pkg>/bin/opencode[.exe]` + package.json），但桌面端 `resources/binaries/` 要的是**扁平命名**
`opencode-{darwin,linux,windows}-{arm64,x64}[.exe]`。

**脚本**：`scripts/sync-opencode-binaries.sh`（已 chmod +x）
- 默认同步 6 个规范目标；`--all` 追加 `-baseline`/`-musl` 变体；`-n` 预演；`--only <name>`；`--src`/`--dst` 覆盖。
- 原子写入（tmp + chmod 755 + mv），落盘后用 `file(1)` 做**架构自检**（arm64|aarch64 vs x86_64|x86-64），不符只告警。
- 缺源即计入 MISSING 并 **exit 1**；预演实测 6/6 命中，合计 768.7 MB。
- 命名映射**与 `electron/backend/opencode.ts::resolveBinFromDir` 的 triples 表逐字一致**，
  **改任一处必须同步另一处**。`resolveBinFromDir` 的兜底是 `startsWith('opencode-')`（readdir 顺序），
  所以 `resources/binaries` 里**别放**额外变体，否则非 preferred 平台可能取错；规范名在 preferred 中优先命中。
