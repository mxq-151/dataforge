## 代码结构解耦审查与重构（审查 + 已实施）

对 /Users/mxq/Desktop/dataforge（Electron + React 19 + TS，约 5.5 万行）做了一次架构耦合扫描，随后按低风险优先顺序实施了 4 项解耦改动。全部通过 `tsc -p tsconfig.json --noEmit` 与 `vite build`。

### 关键事实（后续复查基线）
- 渲染进程宿主桥叫 `window.dataforge`（不是 window.electron），preload 走 contextBridge + sandbox + contextIsolation，安全边界正确。
- `src/bridge/` 是薄封装层（ipc/http/fs/store/shell/path/event），window.dataforge 基本收敛在此，仅 App.tsx 有 3 处越界。
- 主进程 `electron/backend/` 依赖无环：maven 是叶子 → compile/lspPom → compileServer → opencode；lspBridge 独立依赖 eventBus。
- opencode hooks 已拆为 backend / events / chat / sessions 四个子 hook，但编排层 useOpencodeClient 仍 1341 行。

### 发现的主要问题（严重度排序）
1. `src/components/editor/EditorAreaCopy.tsx` 与 `EditorAreaTest.tsx` **diff = 0 完全相同**，各 1030 行，无任何 import 引用 → 2060 行死代码。
2. `src/contexts/AuthContext.tsx:225/250` 直接 `invoke('start_opencode_after_login')` / `invoke('stop_opencode')`，且 login 内混入工作目录计算与 store 写入 → 关注点错配。
3. api 层请求基建 5 份平行实现：index.ts 的 `request()` 之外，codeExecution(6 处 fetch)、dolphinscheduler(4)、fileExplorer(3)、marquez(2) 各写各的超时/错误处理。
4. IPC 契约弱类型：`invoke<T>(cmd: string, args?: Record<string, unknown>)`，主进程用 `Record<string, fn>` 字符串分发，调用点靠手写泛型 + `as unknown as`。
5. `src/bridge/fs.ts` 缺 symlink 封装，导致 `src/App.tsx:442` 裸调 `window.dataforge.fs('symlink', ...)`。
6. hooks 层反向依赖组件层：`src/hooks/useProgramRunner.ts:9` → EditorArea；`src/hooks/opencode/useOpencodeClient.tsx:37` → FileReviewPanel。
7. `electron/backend/opencode.ts:16` 直接依赖 compileServer 拿 endpoint → 跨领域耦合。
8. 持久化方式不统一：LoginPage / DataExploreEditor 直接用 localStorage，而项目已有 bridge/store（userData/df-stores）。

### 客观说明（非深层耦合，勿误判）
- `task-forms.tsx` 2105 行实为 30+ 个并列独立表单（每个 30-80 行），属文件粒度问题，非逻辑耦合。
- views 层无硬编码 URL、未绕过 api 层、无 localStorage 滥用以外的越界。

## 已实施的解耦改动（本日第二批）

### 1. 删除 2060 行零差异死代码
`EditorAreaCopy.tsx` / `EditorAreaTest.tsx`（各 1030 行，diff=0）已移出，备份在
`.workbuddy/dead-code-backup/`，确认无误后可彻底删除。
注：环境禁用 `rm -rf` 与 Finder 删文件（权限违例 -10004），故用 `mv` 到备份目录。

### 2. 补齐 symlink 封装
`src/bridge/fs.ts` 新增 `symlink(linkPath, target)`（对应主进程 electron/ipc.ts 的 symlink op）。
`src/App.tsx` 三处改为经 bridge 调用 → **`window.dataforge` 现已 100% 收敛在 src/bridge/ 内，零越界**。
坑：App.tsx 若静态 `import { mkdir, symlink } from './bridge/fs'`，会破坏 useOpencodeClient /
useFileSystem / SubmitToSchedulerModal 三处对 bridge/fs 的动态加载（构建报 INEFFECTIVE_DYNAMIC_IMPORT）。
已改为 `const fsPromise = import('./bridge/fs')` 保持懒加载。

### 3. 拆分 AuthContext 关注点
- 新建 `src/services/opencodeLifecycle.ts`：导出 `OPENCODE_CONFIG_STORE`、
  `syncWorkspaceConfig` / `startOpencodeAfterLogin` / `stopOpencode`。
- 新建 `src/utils/workspacePath.ts`：`getPlatformDefaultWorkspace` 原是纯函数却放在 hooks 层，
  迁到 utils 后 hooks/useFileSystem.ts re-export 保持兼容（该常量 DEFAULT_WORKSPACE 也被 9 处引用，需一并导出）。
- AuthContext 300 → 280 行，只保留认证职责。

### 4. 统一 api 层请求基础设施
- 新建 `src/api/httpCore.ts`（**零模块依赖**的纯工具，token/host 由调用方传入以避开
  index ↔ httpCore 循环依赖）：`HTTP_STATUS_MESSAGES` / `statusMessage` / `buildQuery` /
  `buildUrl` / `bearerHeader(token, extra)` / `createTimeout(ms)→{signal,dispose}` /
  `ensureOk(res)` / `ensureOkWithBody(res)`。
- 已接入：index.ts(request)、codeExecution(6 处)、fileExplorer(3 处)、systemAudit(1 处)、
  marquez(2 处)、dolphinscheduler(4 处)。
- 消灭：`new AbortController` 仅剩定义处 1 个；手写 `Bearer ${token}` 仅剩定义处 + index.ts。
- 刻意保留：marquez/dolphinscheduler 的**连接测试**仍返回原始 statusText（`HTTP 502: Bad Gateway`），
  第三方系统诊断需要原始信息，不套中文映射。dolphinscheduler 上传资源超时保持 120s。

### 构建注意事项
`npx vite build` 默认会清 dist/assets（71 文件）触发环境批量删除护栏（阈值 50）而失败。
验证时改用 `npx vite build --outDir /tmp/xxx --emptyOutDir`。
