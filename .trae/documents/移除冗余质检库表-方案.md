# 移除冗余质检库表（data_quality_check_result + 项目私有 DQC 表）

## 背景

平台数据质量现状是「两套存储并存」：

- **平台公共层**（元数据库，全平台共用）：`dq_rule_template` / `dq_rule` / `dq_rule_result`。质量大盘、试跑基线（`DqExecutionService.resolveBaseline`）、资产目录质量摘要（`AssetCatalogService.quality`）全部读这里。这是**权威落点**。
- **项目私有层**（业务数据源 schema，如 `dqc_olist_test.dqc_olist_rule_d` / `dqc_olist_result_d`）：由 S2/S3 提示词推导生成，质检程序双写。**平台无任何代码读取它**，属只写不读的死数据。

另有一张历史表 `data_quality_check_result`：已被 `dq_rule_result` 取代，前端零调用、测试零覆盖、仅剩 6 个兼容端点。

目标：删掉 `data_quality_check_result`；让生成契约不再产出项目私有 DQC 库表（**保留 DQC 作为质检程序的代码分层**）；并清理本地已生成的样例工程。

用户已拍板：① DQC **保留代码层，只去表**；② 本地样例**一并清理**。

- `dto/DataQualityCheckResultDTO.java`
- `vo/DataQualityCheckResultVO.java`

- `src/main/resources/mapper/quality/DataQualityCheckResultMapper.xml`

**SQL init（4 方言，`src/main/resources/sql/init/dataforge-{postgresql,mysql,mariadb,h2}.sql`）**：删掉该表的建表/索引/注释块，仿 2026-10-09 下线先例**保留一段「已下线」注释说明**（不写 DROP、不加迁移脚本——本项目无 migration 机制，init 是 schema 唯一来源）。同步清理各脚本里「平台侧原先只有结果表 data_quality_check_result」这类描述性注释。

**前端**：`dataforge/src/api/quality.ts:6` 的注释提到「`/api/quality/check-result/*` 保留兼容」——改成新链路口径（本文件无 check-result 方法，仅改注释）。

**已部署库**：init 改动不会自动从现网库删表，需手工 `DROP TABLE data_quality_check_result;`（在验证章节给出命令）。

## 二、生成契约：不再产出项目私有 DQC 库表（保留代码层）

改动集中在 `dataforge/src/hooks/opencode/opencodeInstructions.ts`，三处措辞 + 一条强约束：

1. **L140（分层规范 LAYERING_SPEC）**：`DQC 质量层：质量规则定义与稽核结果存储`
   → 改为「DQC 质量层：数据质量校验程序（质检任务）的归属层；规则定义与校验结果**不落数仓表**」。
2. **L149（表名命名规范 TABLE_NAMING_CONVENTIONS）**：库/表名前缀列表去掉 `dqc_`。
3. **L462（文档与 DDL 命名规范）**：`ddls/{分层}_ddl.sql` 的示例去掉 `dqc_ddl.sql`。
4. **新增强约束**（放在「质检结果回传规范」L706-734 或 `QUALITY_RULE_SPEC` 处）：明确「规则定义与校验结果**只**通过平台 `POST /api/quality/rule/register` 与 `POST /api/quality/run/report` 登记/回传，**禁止在数仓内建质量规则表 / 结果表**」。

**刻意不动**（保留代码层所需）：
- `programLayout.ts` 的 `WAREHOUSE_LAYERS`（含 `dqc`）与菜单门禁（`code/dqc` 仍需可配置）、`programLayout.test.ts`。
- `asset_category` 的 `dqc` 层种子（4 方言 init）与 `TableNameConventionParser` 的 dqc 分层解析。
- `prodDatabaseGuard.ts` 的 `dqc_` 前缀识别（纯兜底，无害）。

**测试影响**：无。分层契约测试只锁 `ODS/DWD/DWS/ADS`；DDL 产物测试锁的是泛化占位符 `ddls/{分层}_ddl.sql`；`qualityContract.test.ts` / `QualityRuleTypeContractTest.java` 只锁 7 类规则类型。改完 `opencodeInstructions.test.ts` 应全绿。
