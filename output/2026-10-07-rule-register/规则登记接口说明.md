# 规则登记接口实现说明

完成日期：2026-10-07
目标：把关联键从 `rule_name` 字符串换成 `rule_id`，让改名不再断链。

---

## 一、接口契约

### `POST /quality/rule/register`

**语义**：幂等登记。按 **「规则名 + 库 + 表」** 判定同一条规则，已存在则原样返回既有记录（**不覆盖**），
不存在才创建。创建路径完全复用 `create` 的既有校验（7 类规则类型、字段级必须给字段、跨表必须给对照表）
与 `bindTemplate` 的模板自动绑定，不另起一套。

**请求**（`QualityRuleSaveDTO`，取登记必需字段即可）：

```json
{
  "ruleName": "R_AD_001 事件主键唯一",
  "ruleType": "PRIMARY_KEY_UNIQUE",
  "datasourceName": "hive-prod",
  "databaseName": "test_db",
  "tableName": "dwd_event_f",
  "columnName": "event_id",
  "expectedValue": "重复=0",
  "disposeMode": "BLOCK"
}
```

**响应**（`QualityRuleRegisterVO`）：

```json
{ "code": 200, "message": "success",
  "data": { "ruleId": 21, "ruleName": "R_AD_001 事件主键唯一",
            "ruleType": "PRIMARY_KEY_UNIQUE",
            "templateCode": "PRIMARY_KEY_UNIQUE", "created": true } }
```

**鉴权**：与其余接口一致，需要登录态（`Authorization: Bearer <token>`）。
**错误**：缺规则名 / 缺表名 / 规则类型非法 / 字段级未给字段 → 业务异常，HTTP 200 + `body.code`。

### 顺带：`GET /quality/rule` 增加 `ruleName` 精确匹配参数

登记前查「这条规则在不在平台」用得上。用**精确匹配**而非模糊：模糊会一次捞回一堆同名子串。

## 二、为什么判定键是「规则名 + 库 + 表」

这不是随手定的，必须与 **`DqRunService.resolveRuleId` 的反查口径逐字一致**——否则会出现
「登记到 A、回传匹配到 B」这种最难查的错配：结果行指向了另一条规则，界面看着一切正常。

| 位置 | 判定/反查键 |
|---|---|
| `DqRuleService.findByIdentity`（登记） | 规则名 + 库 + 表 |
| `DqRunService.resolveRuleId`（回传反查） | 规则名 + 库 + 表 |

三段限定的理由：规则名只在**单个设计文档内**唯一（提示词原话），跨库表可能重名。

**已知局限**：判定键不含数据源，因此**两个数据源下同名库表 + 同名规则会被视为同一条**。
这是沿用既有反查口径的代价（改判定键要同时改回传反查，否则破坏一致性），已在此记录。

## 四、一处必须订正的事实

之前（含项目笔记）说「回传只靠 `DATAFORGE_QUALITY_REPORT_TOKEN` 令牌级鉴权」——**这个说法是错的**。

实际核实结果：

| 项 | 事实 |
|---|---|
| `DATAFORGE_QUALITY_REPORT_TOKEN` 在后端 | **零匹配**：后端代码、配置里都没有这个变量 |
| 它究竟在哪 | 只存在于**前端提示词**（`opencodeInstructions.ts`）与 api 注释里 —— 它是**给生成程序的约定**，不是后端配置项 |
| `/quality/run/report` 的真实鉴权 | `SecurityConfig` 是 `.anyRequest().authenticated()`，report 不在 `permitAll` 名单 ⇒ **需要真实 JWT** |
| 所以那个环境变量的语义 | 它装的就是**用户的 bearer token**，程序把它放进 `Authorization: Bearer {令牌}` |

结论：回传/登记都靠**登录态 JWT**，没有独立的令牌级通道。这也意味着**生成程序的令牌权限等于发放者的用户权限**——
`DqRunService.hasTableReadAccess` 那个死代码本来该在这里起作用（见第六节）。
