## 结论速览

**方向一（前端调了、后端没实现）：0 处。**
前端 `api/assetCatalog.ts`（31 个方法）与 `api/quality.ts`（26 个方法）声明的每一条路径，在 dataforge-server 里都有对应的控制器映射，且都是**真实实现**（Service 有落库/校验逻辑，不存在 `UnsupportedOperationException` 空壳）。后端控制器的 Javadoc 甚至直接引用了前端契约文件名，说明两侧契约是对齐的。

**方向二（后端有、前端 UI 没接）：缺口全部在这里，共 30 条。**

| 模块 | 后端已有端点 | UI 实际调用 | **未接线** |
| --- | --- | --- | --- |
| 资产管理 `/asset/*` | 28（另 3 个内部任务端点） | 8 | **23** |
| 数据质量 `/quality/*` | 30 | 19 | **7**（其中 1 条设计如此） |
| 后端独有、前端零调用 | `/asset/task/*/run` ×3、`/quality/check-result/*` ×6 | 0 | 9（内部/遗留，非缺口） |

一句话：**缺口不在「接口没写」，而在「接口写了没接线」**——后端跑在前端 UI 前面，前端两个面板里有大量静态占位区块与死控件。

**归为两处 UI 缺口：**

1. **「规则模板」页签是纯本地契约渲染**——`DataQualityPanel.tsx` 的 `TemplateTab` 直接 map `types/quality.ts::QUALITY_RULE_TYPES` / `QUALITY_DISPOSE_MODES`，页内文案自述「服务端接口就绪后以服务端模板为准」。因此**自定义模板的增删改查 + SQL 预览这 5 条后端接口完全悬空**，前端没有任何维护入口。
2. **「运行记录」只到列表 + 结果两级**——`RunTab` 用 `listRuns` + `listRunResults`，没有「运行实例详情」；页签规划里的「执行 SQL 与异常明细」「一键跳转调度实例详情」均未实现，`getRun` 悬空。

### 2.3 后端独有（前端零调用）

`/quality/check-result/*` 共 6 个端点（`GET /list`、`GET /{id}`、`POST`、`PUT`、`DELETE /{id}`、`GET /statistics/fail`）——`DataQualityCheckResultController` 明确为**既有结果接口，保留兼容**，新链路已走 `/quality/rule|task|run/*`。前端（含 `api/quality.ts`）零引用，属**遗留端点**，可按计划下线或保留兼容。

## 三、建议的接线优先级

按「后端已就绪、前端接线成本低、对现有面板收益大」排序：

**P0 —— 让已有控件真正工作（改动最小）**
1. 左栏搜索框接 `search`（`keyword` 传入请求或独立触发），`suggest` 做联想
2. 「刷新」按钮接 `getCatalogTree` 重拉
3. 「我的收藏」接 `listBookmarks`（顺带 `addBookmark`/`removeBookmark`）
4. `reportAccess` 埋点开闸——否则热度/访问频率类 4 张卡片长期空转

**P1 —— 补齐资产详情（复用现成契约）**
5. 详情页签 `DETAIL_TABS` 由装饰改为真页签，逐个接 `getTableUsage` / `getTableIndicators` / `getTableProducers` / `getTableQuality` / `getTableDoc`
6. 治理项区块接 `getInventoryHealth` + `getInventoryOverview`（+ `getAnnotationGaps`）
7. 写能力补 `updateOwner` / `updateCategory` / `updateTags`（`updateLifecycle` 已有样板可直接照抄）

**P2 —— 质量侧补两块**
8. 「规则模板」页签加自定义模板 CRUD + SQL 预览（后端 5 条接口现成）
9. 「运行记录」加实例详情（`getRun`）

**可不动**
- `previewTable`（数据预览，设计上跳「数据探索」模块）
- `saveTableDoc` / `listDocHistory`（使用说明复用知识库能力，需先定边界）
- `refreshTableMetadata`（与元数据同步模块重叠）
- `refreshTableMetadata`、`reportRun`、`/asset/task/*/run`、`/quality/check-result/*`
