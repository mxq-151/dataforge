## 三、关键设计决策

1. **`reportAccess` 只上报有具体资产的动作**（选中表 = browse、打开预览 = read、新增收藏 = bookmark）。不上报「检索」：服务端 `recordAccess` 对 `assetId == null` 直接丢弃，为避免写入 `assetId=0` 的脏埋点，宁可少报一个 accessType。
2. **分类与标签不做自由文本兜底**。字典接口（`listCategories` / `listTags`）不可用时降级为「当前值只读 + 说明」，不放开输入 —— 否则会写入服务端不认识的编码。
3. **标签是整体替换语义**，因此界面以复选框维护本地集合，提交最终集合；分类属性一次提交四个字段（`categoryCode` / `topic` / `visibility` / `assetLevel`）。
4. **写成功后由宿主重拉详情，不自行改本地副本**（生命周期是唯一例外，沿用既有的就地回填）。原因是 `categoryCode` 清空后服务端会按表名重新解析分层与业务域，本地推测会与服务端结果漂移。
5. **详情页签各自探各自的口**，一个页签不可用不影响其它页签；页签级降级文案沿用「服务端 {路径} 尚未接入 + 能力清单」的既有范式。
6. **「权限」页签不造接口**：权限在服务端 fail-close 生效（越权表名/字段名不下发），页签只做只读说明 + 回显可见性/等级/负责人，明确写出「无独立端点」。
7. **「血缘」页签不重复实现**，仍是跳数据血缘模块（Marquez 客户端）——与原设计边界一致。
8. **模板校验前置对齐服务端**：`DqRuleTemplateService.validate` 的单条 SELECT/WITH、7 类归属、编码名称非空三条硬约束在提交前先拦一次；内置模板（`assertCustom`）界面不提供编辑/删除/启停入口。
9. **SQL 预览放在模板页签内自带选表**：`preview-sql` 必须知道目标表才渲染得出方言 SQL，因此预览弹窗内提供数据源 → 库 → 表 → 字段选择，数据源清单走 `api/datasource` 懒加载（仅在打开弹窗时请求），不引入 `DataSourceProvider` 依赖。
10. **检索/收藏是右栏视图而非新页签**，模块级页签仍只有「资产概况 / 资产目录」两个，不改一级信息架构。
