# 质量规则「中间档」改进说明

完成日期：2026-10-07
背景：见前序讨论——「让智能体获取规则模板再生成质检代码」能解决**实现走样**，但解决不了**名称漂移**。
中间档 = 模板下发 + 规则类型→模板自动绑定 + 回传带 ruleId/execSql。

---

## 一、三件事的落地情况

| 中间档的组成 | 落地前的状态 | 本次动作 |
|---|---|---|
| 规则类型 → 模板自动绑定 | **已实现**（`DqRuleService.bindTemplate`，L381） | 未改，仅核实并写进契约测试 |
| 模板 SQL 骨架下发给 S3 | 缺失：`QUALITY_RULE_SPEC` 只给了 7 类的 label + desc | **新增** `buildQualityTemplateSpec()` + 提示词章节 |
| 回传带 ruleId / execSql | 缺失：DTO 无字段，落库只用 rule_name | **新增** DTO 两字段 + `resolveRuleId()` 回填 + `exec_sql` 落库 |

**关联键的变化**（这是本次的实质）：

| | 改造前 | 改造后 |
|---|---|---|
| 程序回传 → 平台规则 | 只有 `rule_name` 字符串 | `ruleId` 显式传入优先；未传则按「规则名 + 库 + 表」反查回填 |
| 规则级结果 → 历史基线 | 断的（基线按 `rule_id` 取，回传不落 rule_id） | 通了，且向下兼容：查不到时落 null 且不报错 |
| 当时跑了什么 SQL | 无记录（`exec_sql` 列为空） | 回传 `execSql` 即落库，可事后核对口径 |

## 三、几个刻意的设计选择

1. **模板章节只给 S3**。S1/S2 只消费术语表；给他们下发 SQL 骨架会被误读成"照模板写规则"。数据探索模块按 `moduleName` 短路，也不带。
2. **拉取失败不写缓存**。空结果可能是"平台还没配"也可能是"这次没拉到"，不缓存才能让下一轮自然重试；成功且非空才缓存。
3. **反查用三段限定**（规则名 + 库 + 表），避免跨库同名规则误配。
4. **查不到规则不报错**。回传失败不得改变校验任务成败是既有约定；规则尚未登记同样不该让整条回传失败——落 null 保底，结果仍自包含。
5. **不用模板字符串拼 SQL 骨架**。骨架里含 `${占位符}`，写进 TS 模板字符串会被当插值吃掉，所以 `buildQualityTemplateSpec` 用数组 + 字符串拼接。测试里有专门一条断言占位符原样保留。
6. **自定义模板一并下发但不缓存**：提示词里约定"同类型优先用内置模板"，数组顺序即优先级。

## 五、一处订正（前序回答里的不准确表述）

之前说「**告警订阅只存不发**」不够准确，实际是三层：

| 层 | 状态 |
|---|---|
| 订阅配置 | 有（`dq_alert_subscription`，page/save 两个接口） |
| 告警**登记** | **有**，但仅在平台执行路径：`DqRunService.registerAlerts()`（L233 调用）写 `dq_alert_log`，`status=PENDING`、`failReason="告警通道尚未接入，已登记待发"` |
| 告警**发送** | 没有：`dq_alert_log` 全仓无任何消费方；且**程序回传路径根本不登记**（`reportRun` 没有 `task`，也就调不到 `registerAlerts`） |

所以准确说法是：**订阅可配、平台执行路径会登记待发告警、发送通道未接入、程序回传路径既不登记也不发送。**

## 六、仍未做（下一步的候选）

| 项 | 说明 |
|---|---|
| 规则**登记**接口 | 中间档靠"回传时带 ruleId（可反查）"缓解名字漂移。根治要让智能体在生成代码前先调平台接口建规则、拿回 ruleId —— 需要新增接口 + 提示词改造 |
| 重档（S3 不写 SQL） | 对模板可完整表达的规则类，改成"调度节点调平台执行规则集"。表达力与可观测性有代价，建议缓做 |
| 告警发送通道 | 消费 `dq_alert_log` 并实际投递 |
| 调度触发入口 | `DqTask` 有 `triggerType=SCHEDULE` / `workflowCode` / `nodeName`，但只有 `/task/{id}/run`（硬编码 MANUAL），缺调度器可调的触发/回调端点 |
| 回传做表级权限校验 | `DqRunService.hasTableReadAccess` 仍是死代码（零调用点） |
| 程序回传的运行实例归到真实任务 | 目前 `taskName` 落的是规则名、`taskId` 为空 —— 运行记录里看不到它属于哪个质检任务 |
