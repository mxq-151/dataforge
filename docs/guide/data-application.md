# 数据应用

> [文档首页](../README.md) › 使用教程

数据资产沉淀完成后，需要被消费才产生价值。DataForge 的数据应用由五个入口构成：**数据探索**（即席查询与图表分析）、**指标管理**（口径资产化）、**数据血缘**（影响面分析）、**资产目录**（资产检索与画像）、**AI 数据分析师**（对话式取数）。本章说明每个入口的适用场景与使用要点。

## 一、五个入口的适用场景

| 入口 | 解决什么问题 | 典型使用者 |
| --- | --- | --- |
| **数据探索** | 临时取数、验证数据、探查表结构与样本数据 | 数据分析师、数据开发工程师 |
| **指标管理** | 把反复使用的统计口径固化为可复用的指标定义，避免各人各算 | 数据架构师、数据分析师 |
| **数据血缘** | 查「这张表/这个字段从哪来、影响谁」，用于影响面评估与问题定位 | 数据开发工程师、数据架构师 |
| **资产目录** | 检索「有没有这张表」、看资产画像（分层、负责人、生命周期、热度） | 全体角色 |
| **AI 数据分析师** | 用自然语言提问，由智能体代写 SQL 并给出结论 | 业务方、数据分析师 |

## 二、数据探索

数据探索是 SQL 编辑器形态的即席查询入口，支持多会话标签切分不同分析任务，查询结果与执行历史在同一次会话内切换查看。

| 能力 | 说明 |
| --- | --- |
| 库表浏览器 | 按数据源逐层浏览库 → 表 → 字段，可直接查看表结构与样本数据，避免凭记忆写字段名 |
| SQL 编辑器 | 支持语法高亮与表名字段名自动补全（补全来源为已加载的库表元数据） |
| 多会话标签 | 每个标签是一个独立会话；标签名与会话名保持一致，可按任务类型拆分（如「日报核对」「异常排查」） |
| 结果集与执行历史 | 一次执行后可在「结果集」与「执行历史」两个页签间切换；多语句按任务集顺序执行，失败时自动定位到历史页签便于看报错 |
| 图表分析 | 对结果集直接出图，支持表格、柱状图、折线图、饼图、散点图五类，用于快速看趋势、对比与分布 |

> [!NOTE]
> 执行历史按「**后端 host + 当前用户**」隔离落盘。数据探索是平台级模块、无项目维度，因此不同用户在同一台客户端上互不可见彼此的历史；切换后端环境后历史也随之切换，不会串用。

## 三、指标管理

指标是「口径的资产化」。凡是在两个以上场景被反复计算、且业务方认可的统计量，都应沉淀为指标，而不是留在各自的 SQL 里。

- **检索**：支持按指标名称、别名、业务定义搜索，并可按主题域过滤，便于确认「这个指标是否已经存在」；
- **指标详情**：展示主题域、业务定义等口径要素，并列出该指标关联的**字段**及其所在库表；
- **血缘联动**：从指标关联字段可直接跳转到数据血缘，确认该指标的计算链路与上游依赖；
- **口径复用原则**：查询与分析时必须优先复用既有指标口径，不得私自改写；发现口径冲突时应显式说明差异，而不是各写各的。

## 四、数据血缘

血缘是图谱形态的资产关系视图，同时提供**表级**与**字段级**两个粒度：

#### 1. 从资产出发定位节点

在资产目录、指标管理或血缘面板中选中目标表或字段，进入其血缘图谱。

#### 2. 向上游回溯来源

沿上游方向逐层展开 ODS → DWD → DWS，确认字段口径的实际计算路径。

#### 3. 向下游评估影响

沿下游方向展开，列出所有受影响的表、指标与报表，作为变更影响面与重跑范围的依据。

#### 4. 与调度依赖交叉验证

血缘说明数据流向，调度 DAG 说明执行时序，两者结合才能确定重跑顺序。

> [!TIP]
> 血缘数据由**生产环境**提交的作业在运行期自动上报，无需手工登记。因此血缘的完整度取决于：作业是否以 prod 环境提交、DDL 与 SQL 是否规范书写（无法解析的写法会导致字段级血缘缺失）。详见持续集成中的环境闸门说明。

## 五、资产目录

资产目录是「找资产」的总入口，搜索范围覆盖表、字段与指标三个维度，且**仅展示当前用户有权限访问的资产**——无权访问的资产在检索结果中不会出现。

进入单表详情后，按页签查看资产画像：

| 页签 | 包含信息 |
| --- | --- |
| 概览 | 分层 / 业务域 / 负责人 / 主题域 / 可见性 / 生命周期 / 存储量 / 行数 / 最近更新 / 治理项 |
| 字段 | 字段类型、注释与业务描述、主键与分区标记、安全等级、字段热度星级 |
| 分区 | 分区字段、分区记录数与存储量 |
| 血缘 | 表级与字段级上下游，可跳转到数据血缘模块查看完整图谱 |
| 指标 | 该表产出的指标：指标编码、名称、主题域、业务负责人 |
| 产出任务 | 写入该表的调度工作流与任务节点 |
| 数据质量 | 该表的规则数、最近一次校验结果、未通过规则条数 |
| 使用记录 | 浏览与读取趋势、字段热度明细、读取 TOP 人员 |
| 权限 | 当前用户对该表的行 / 列权限（只读展示） |
| 使用说明 | Markdown 形式的使用说明与历史版本 |

热度统计包含浏览数、读取数、收藏数与字段热度（0~5 星），可用于识别**高频使用但缺乏治理**的表——例如热度高但字段无注释、无质量规则的核心表。

> [!WARNING]
> 资产目录的详情页签为规划中的完整形态，其中「使用说明」「数据质量」「产出任务」等内容依赖服务端接口接入进度；若某页签暂无数据，属接口尚未接入，而非资产确实缺失。字段热度与浏览/读取趋势依赖 T+1 汇总任务，当日数据次日可见。

## 六、AI 数据分析师

在数据探索模块中与智能体对话，由智能体代写 SQL、执行查询并以业务语言给出结论。该角色是**旁路角色**：面向即席查询，不参与需求 → 设计 → 开发的文档流转。

### 职责与边界

- **只读不写**：禁止 INSERT / UPDATE / DELETE / DDL 等任何写操作；
- **不产出交付物**：不生成需求文档、数仓设计文档与 ETL 程序，这些属于 S1 / S2 / S3 链路的职责；
- **口径复用**：优先复用已定义指标的口径与计算表达式，发现口径冲突时说明差异并给出建议。

### 查询规范

| 规范项 | 要求 |
| --- | --- |
| 命名查证 | 库名、表名、字段名须经查证，查不到时明确告知，禁止臆造 |
| 结果集限制 | 所有查询必须使用 `LIMIT` |
| 分区过滤 | WHERE 条件优先使用分区字段做时间过滤，必须限定明确时间范围，禁止无界全历史扫描 |
| 可读性 | 复杂分析用 CTE 分步表达并配中文注释说明业务含义；对大表或性能存疑的查询先 `EXPLAIN` 验证再执行 |
| 结果呈现 | 不把结果集整段粘贴到对话中，只汇报汇总结论与必要样本 |
| SQL 落地 | 按**页签（会话）**隔离：每个页签是一个独立会话，对应自己的会话目录，SQL 写入其中的 `user_{username}.sql`（即 `individual/{timestamp}/user_{username}.sql`）——**一页签一文件**，编辑内容自动保存到本页签文件，不追加到统一文件，也不得写入或覆盖其他页签的文件 |
| 敏感数据 | 身份证、手机号、银行卡、姓名、住址等须脱敏后再出现在结果中，禁止明文输出 |

智能体的信息获取顺序固定为：**知识库（业务规范、开发规范）→ 后端元数据服务（库表结构、字段业务含义、数据源）→ 已有指标口径**。这意味着知识库内容的质量直接决定智能体回答的准确性——参见知识管理。

## 七、面向下游的交付

数据应用的最终产出落在 ADS 应用层。交付到下游（报表、接口、数据文件、看板等）的形态由 需求管理阶段的 S1 需求文档中「数据输出方式」章节明确约定，开发阶段据此实现，不在应用层临时决定。

> [!NOTE]
> 对外导出与下载受库表权限的 `canExport` 开关控制。数据应用的「可见」与「可导出」是两个独立权限，详见数据安全。
