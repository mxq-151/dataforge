# 项目管理

> [文档首页](../README.md) › 使用教程

DataForge 平台中的项目是组织开发资源的基本单元，与调度系统、数据血缘系统之间存在明确的映射关系，确保开发、调度、血缘追溯的一致性。

## 概念定义

项目涉及三个核心概念：

| 概念 | 所属系统 | 作用 |
| --- | --- | --- |
| **开发项目** | DataForge | 组织需求、代码、指标、数据源等开发资源，是数据开发的基本单元 |
| **调度项目** | DolphinScheduler | 组织工作流定义、任务实例、资源文件等调度资源，是作业调度的基本单元 |
| **数据血缘命名空间** | Marquez | 隔离不同项目或环境的数据血缘，是数据血缘追踪的边界单元 |

## 映射关系

为确保开发、调度、血缘追溯的一致性，三者之间存在**一对一映射**关系：

- **一个开发项目** → 对应一个调度项目
- **一个开发项目** → 对应一个数据血缘命名空间
- **一个调度项目** → 与一个数据血缘命名空间关联

## 创建流程

在 DataForge 中创建项目时，平台会自动完成三者的关联创建：

1. **创建开发项目** — 在 DataForge 中创建项目，填写项目名称、描述、负责人等信息
2. **创建调度项目** — 请手动在 DolphinScheduler 中创建同名调度项目
3. **自动创建血缘命名空间** — 平台自动在 Marquez 中创建同名命名空间
4. **关联配置** — 平台记录三者的映射关系，确保后续操作的一致性

> [!WARNING]
> **注意**：项目创建后，调度项目和血缘命名空间的名称**不可修改**。如需调整，需重新创建项目并迁移代码和工作流。

## 项目划分要求

项目按组织架构进行划分，遵循**事业部 → 产品线**的层级关系：

- **一个项目对应一个事业部** — 项目是事业部的数据开发单元，承载该事业部下的所有数据资产
- **事业部下分产品线** — 每个产品线对应项目中的一个子目录，隔离不同产品线的开发资源

例如：交易事业部下包含支付产品线和结算产品线，则在项目中对应 `pay/` 和 `settle/` 两个产品线目录。

## 项目目录结构

每个项目遵循统一的目录结构规范，按产品线组织开发资源：

```
project-name/                    # 项目（对应事业部）
├── {product-line}/              # 产品线目录
│   ├── docs/                    # 开发需求及数仓设计文档
│   ├── ddls/                    # 建表语句
│   └── procs/                   # 数据处理程序
│       ├── dim/                 # 维度表
│       ├── dwd/                 # 明细层
│       ├── dws/                 # 汇总层
│       ├── dqc/                 # 数据质量检查
│       └── ads/                 # 应用层
└── ...
```

## 调度工作流命名规范

调度工作流名称与项目目录结构保持一致，规则如下：

- **工作流名称** — 等于处理程序文件所在父目录路径的拼接（到产品线层级），目录层级间用下划线连接
- **任务名称** — 每个处理程序文件对应一个调度任务，任务名称即文件名（不含扩展名）

例如，文件路径为 `pay/procs/dwd/order_detail.sql`，则：

- 工作流名称：`pay_procs_dwd`（产品线 `pay` + 分层 `dwd`）
- 任务名称：`order_detail`

> [!NOTE]
> **建议**：指标开发应严格遵循分层依赖关系，避免**跨层依赖**（如 ADS 直接依赖 ODS）和**反向依赖**（如 DWD 依赖 ADS），以保证数据链路清晰、便于血缘追溯与影响分析。跨产品线的数据依赖应通过血缘命名空间隔离，避免隐式耦合。
